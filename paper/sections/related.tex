\section{Related work}
\label{sec:related}

\paragraph{Memories a model writes.} MemGPT pages summaries in and out of the context window \citep{packer2023memgpt}; Mem0 extracts facts from each exchange and adds, updates or deletes entries in a vector store \citep{chhikara2025mem0}; Zep builds a temporal knowledge graph \citep{rasmussen2025zep}; A-MEM links model-written notes \citep{xu2025amem}. All of them pay a model once per exchange to build the memory and store the model's words in place of the user's.

\paragraph{Latent memories.} These replace text with vectors that a model reads directly: xRAG compresses a document to one token \citep{cheng2024xrag}, and Memorilla trains a memory module that gathers query-relevant information from an encoded collection into 16 tokens \citep{fallahpour2026memorilla}. These need training against each base model and access to its embedding layer, whereas Memorable works with a frozen reader behind a hosted API.

\paragraph{Retrieval over the raw turns.} Hybrid retrieval with reciprocal rank fusion \citep{cormack2009rrf} and cross-encoder reranking \citep{chen2024bgem3} are standard in search. LongMemEval's own analysis of memory design found that storing the rounds of a conversation scores higher than storing facts extracted from them on every question type but multi-session reasoning \citep{wu2025longmemeval}. Our retrieval-only run also trails Mem0 there. Memorable builds on that finding: a hybrid retriever over verbatim turns, plus a planner, two rules on the retrieved list and fixed reader rules, is built by fixed code and ties a memory that a model wrote on BEAM-1M under one judge. We evaluate on BEAM \citep{beam2026} and LongMemEval \citep{wu2025longmemeval} and registered a prediction before every run (Appendix~\ref{app:predictions}).
