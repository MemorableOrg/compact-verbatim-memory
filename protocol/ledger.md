## Edge cases per ability and the fix for each (all at question time; memory build stays $0)
- Instruction / preference: the rule is said once, hundreds of messages earlier, and never searched for. Fix: standing-rule pool always shown (A47). Edge: a rule later revoked or changed. Fix: show the pool in date order and tell the reader the latest statement of a rule wins.
- Multi-session: facts spread over several sessions; one query finds one session. Fix: planner splits into 2 to 4 queries, each fused; wide k (60). Edge: counting questions ("how many times"). Fix: reader rule to list each instance with its date before giving the count.
- Temporal: relative time ("two weeks after the launch"), and dates only on some messages (time_anchor inherited). Fix: every excerpt shows its absolute date; reader rule to resolve relative references against those dates and show the arithmetic. Edge: several messages with the same anchor date; keep message order.
- Event ordering: needs every event, in order. Fix: planner type "order" gets wide k; excerpts sorted by date and message id; reader lists one event per line with date. Edge: duplicate mentions of one event; reader rule to merge duplicates.
- Knowledge update / contradiction: the old value and the new value both retrieved. Fix: date order plus "most recent wins, mention the change" (already ahead on contradiction; keep it).
- Abstention: question about something never discussed; retrieval always returns something. Fix: keep the existing rule "say there is no information"; do not add a score threshold (risk of false abstention on hard lookups).
- Summarization: needs coverage, not one fact. Fix: planner type "summary" gets wide k; reader rule to cover each phase in date order.
- Long assistant messages truncated at 256 tokens for embedding. Edge: answer sits deep in a long message. Fix candidate: also embed the first 256 tokens of each half of messages over 400 tokens, max over parts (dev test).

## Approaches considered and why chosen or not
- Planner (one gpt-5-mini call, ~$0.0005): chosen; targets the three biggest gaps.
- LLM fact extraction like Mem0: rejected; that is the cost we avoid, and it lost contradiction badly.
- Learned reranker fine-tune (InfoNCE on 100K/500K gold message ids): next if planner leaves multi-session or temporal behind; trains on dev only.
- Score-threshold abstention: rejected for now (false abstentions).
- Map-reduce over the full chat for summaries: too costly per question at 1M; wide k instead.
